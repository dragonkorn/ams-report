## หลักคิด

**ไฟล์ต้นฉบับคือคำตอบ** ทุกตัวเลขบน xlsx 5 หน่วยนั้นทำมือจาก CSV ชุดเดียวกับที่เราอ่าน
ถ้าเราคำนวณแล้วไม่ตรงกับเซลล์นั้น แปลว่าเราผิด

```bash
cd app
npm run fixtures   # ต้องรันก่อนครั้งแรก
npm test           # 140 tests
```

test จะ **ข้ามอัตโนมัติ** ถ้าไม่มี `app/fixtures/` (`describe.skipIf`) — CI ที่ไม่มีไฟล์ตัวอย่างจะไม่พัง

## fixtures

`exampleFiles_2/` มี 5 zip ชื่อไทย ข้างในชื่อไฟล์ก็ TIS-620 ซึ่ง `unzip` บน macOS แกะไม่ได้

`scripts/extract-fixtures.mjs` อ่าน zip เอง — เดิน central directory + `inflateRawSync` ไม่พึ่ง dependency
decode ชื่อไฟล์ด้วย `windows-874` แล้วเขียนออกเป็นชื่อ ASCII:

```
app/fixtures/vp7/
  AMSDailyKRACase.csv  AMSDailyKRACase_(1).csv  …  (8 ไฟล์)
  report_vp7.xlsx
  report_vp7.pdf
```

`fixtures/` อยู่ใน `.gitignore` — สร้างใหม่ได้เสมอจาก `exampleFiles_2/`

### ห้ามมีข้อมูลจริงใน repo — repo นี้เป็น public

`exampleFiles*/` · `*.xlsx` · `*.csv` · `*.pdf` · `*.zip` ถูก ignore ทั้งหมด และ**ห้ามเขียนลงไฟล์ใด ๆ**:

```
รหัสตัวแทน · ชื่อ-ชื่อย่อ · เบี้ย/FYC/FYP รายคน · รหัสหน่วย · ยอดระดับหน่วย
```

ตัวอย่างในเอกสารและ test ใช้ชื่อ/รหัส**สมมติ**ทั้งหมด (`100017 : สมชาย ใ.`)
test ที่ต้องอ้างถึงคนใดคนหนึ่งให้หาแถวด้วย**คุณสมบัติ** เช่น `status === 'suspended'` ไม่ใช่รหัส

ตรวจก่อน push: ดึง roster จริงจาก `fixtures/` มาไล่เทียบกับทุกไฟล์ที่ track ไว้ ต้องไม่เจอสักตัว

## test ที่มี

### `golden.test.ts` — ตัวเลขตรงต้นฉบับ

ต่อหน่วย (5 หน่วย) เทียบทุกแถว:

```
10 คอลัมน์ตัวเลข        Case/FYP/FYC สะสมปี + นำส่ง/อนุมัติ/FYC เดือน
ขั้นบันได FYC            ช่อง "ต้องมี" ตรงกับที่พิมพ์ไว้
ผลรวมกริด = Case สะสมปี  รายคน
ช่องเดือนปัจจุบัน        = Case MTD Current Year
x/12                     นับตรง
```

บวก: แถวสรุปหน่วยจากไฟล์ Agency · รหัสหน่วยจากไฟล์ Agency · ชื่อย่อ · FYC ladder

**ข้ามเซลล์ที่ต้นฉบับพิมพ์ผิดมือ** (`0` และ `1/12.`) — `normaliseActive()` กรองออก
ไม่ใช่การหลบ test แต่เพราะค่าที่ระบบควรผลิตคือค่าที่ถูก ไม่ใช่ค่าที่คนพิมพ์พลาด

### `report.test.tsx` — ทั้งสายจนถึง HTML

CSV → snapshot → นำเข้า xlsx seed → `buildReport` → `renderToStaticMarkup`

ยืนยัน:
- **21 คนขึ้น report จาก 25 คนใน CSV**
- `gridMismatches` ว่าง
- ตัวเลขในหน้าตรงกับ xlsx (Active, ต้องมี FYC, ยังขาดอยู่)
- รูปแบบตัวเลขไม่มีทศนิยม
- พักสัญญายังอยู่ · ตัดสัญญาหายไป
- คลาสไฮไลต์แถว `row-suspended` / `row-produced` ออกจริง

**test ที่จงใจทำผิด** — บันทึกข้อมูลเดือน ก.ค. ใต้วันที่เดือน ส.ค. แล้วยืนยันว่าระบบ**ต้องจับได้**:

```
ทุกคนที่มีงานอนุมัติเดือนนี้ กริดจะนับ ก.ค. 2 รอบ  →  ต้องโผล่ใน gridMismatches ทุกคน
```

กันไม่ให้บั๊กข้อ 1 ใน [05-pitfalls.md](05-pitfalls.md) กลับมาเงียบ ๆ อีก

### `xlsxExport.test.ts` — round-trip

export แล้วอ่านกลับด้วย importer ของเราเอง เทียบทีละคน:
วันที่ออกรหัส · MOC · สถานะ · กริด 12 เดือน · Limra 4 ค่า · Limra ระดับหน่วย · ข้อความปลุกใจ · วันที่ในไฟล์ · หน่วย

พิสูจน์ว่าไฟล์ที่ส่งออกไปทำงานต่อใน Excel แล้ว **เอากลับเข้าระบบได้** เพราะใช้ผังเซลล์เดียวกัน

### `colors.test.ts` — กฎสีทุกข้อ

export VP7 แล้วอ่าน `fill.fgColor.argb` กลับ ตรึงกฎใน [02-report-spec.md](02-report-spec.md#กฎระบายสีรายเซลล์ในแถวตัวแทน)
ครบทุกข้อ: ไฮไลต์ B–H · ตัวอักษรแดงใน H · M–R ที่ผูกกับ N · สีไตรมาส · เทาเดือนที่ผ่านไป · AI/AJ/AK/AL · แถบ Limra

**กวาดทุกแถวในหน่วย ไม่ใช่เลือกบางคน** — วนทั้ง 21 แถว เทียบทีละช่องกับกฎที่เขียนไว้ในไฟล์ test เอง
(ไม่ import helper จาก `compute.ts` มาใช้ ไม่งั้นกลายเป็นทดสอบตัวเองกับตัวเอง)

**ห้ามอ้างรหัสหรือชื่อตัวแทน** ท้าย test มีข้อยืนยันว่าหน่วยนี้มีเคสครบทุกแบบ
(คนพักสัญญา · คนมีงานอนุมัติ · คนมี FYP แต่ Case ไม่มา · คน FYC ครบ · คนที่ปีนี้ไปไม่ถึงแล้ว)
ไม่งั้นการกวาดจะผ่านฟรีถ้าไม่มีเคสนั้นเลย

อีก 2 test ในไฟล์เดียวกัน: **บล็อกสรุปหน่วย** (สีรายคอลัมน์ · แถว FYC เป็นฟ้า · Growth ติดลบตัวแดง)
และ **ชื่อเดือนหมุน 90°** พร้อมความกว้าง S < 4

หาแถวบล็อกสรุปด้วยการไล่หาเซลล์ `B` ที่เป็น `Case` เพราะบล็อกไหลตามจำนวนคน

### `limraPaste.test.ts` — ตาราง Limra ที่ก๊อบจากเว็บ AIA

อ่านก้อนจริงทั้ง 4 แบบจาก `exampleFiles_2/limra.txt` (ถูก ignore เหมือน fixtures → `describe.skipIf`)

**ห้ามเขียนค่าจากไฟล์นั้นลงใน test** ทุกข้อยืนยันเป็นอย่างใดอย่างหนึ่ง:
- รูปร่าง (`shape` · `section` · จำนวนแถว)
- ค่าที่อ่านจากบรรทัดเดียวกันตอนรัน แล้วเทียบกับสิ่งที่ parser ทำกับบรรทัดนั้น

เคสที่ก้อนจริงไม่มี ใช้รหัส/ชื่อสมมติ (`0000000001 : นาย หนึ่ง ทดสอบ`)

ครอบคลุม: แมปคอลัมน์ทีละแถว · แยก YTD/P12M จากหัวตาราง · ก้อนหน่วยเอาสองตัวแรก ·
ค่าติดลบและ `0.00` · ไม่มีหัวตาราง → ต้องถามผู้ใช้ · ไม่มี tab → ไม่ยอมอ่าน ·
แมตช์ 0 → บล็อก · `ended` → ข้าม · คนที่ไม่มีในก้อน → ค่าเดิมคงไว้ ·
ช่องว่างไม่ทับของเดิม · วางซ้ำค่าเดิมแล้วไม่มีอะไรเปลี่ยน · หัวตาราง Limra สองสะกดต้องแกะวันที่ได้ทั้งคู่

**ยืนยันว่าก้อนตัวอย่างยังมีเคสครบ** — ถ้าวันหนึ่งไม่มีเบี้ยติดลบหรือค่า `0.00` เหลืออยู่
test จะฟ้อง ไม่ใช่ผ่านฟรี (หลักเดียวกับ `colors.test.ts`)

### `replay.test.ts` — เปิดรอบเก่าแล้วต้องได้ของเดิม

ไม่ใช้ fixtures — สร้าง snapshot สมมติ 3 รอบ (พ.ค. · มิ.ย. · ก.ค.) แล้วตรึง 3 ข้อ:
1. กรอง `asOfDate <= รอบที่เลือก` แล้ว กริดโชว์เฉพาะเดือนที่เกิดไปแล้ว
2. ไม่กรอง → เดือนหลังจากนั้นโผล่ขึ้นมา (คือกับดัก [05-pitfalls.md](05-pitfalls.md) ข้อ 14)
3. มี seeded ต้นปี → ผลรวมกริด = งานอนุมัติสะสมปี **ของรอบนั้น** ทุกรอบ

## ที่ยังทดสอบอัตโนมัติไม่ได้

| เรื่อง | ทำไม | ต้องทำยังไง |
|---|---|---|
| การเรนเดอร์ PNG | ต้องมีเบราว์เซอร์จริง | กดปุ่มลองเอง ดูว่าฟอนต์ไทยไม่เพี้ยน |
| PDF จาก `window.print()` | เช่นกัน | สั่งพิมพ์ → Save as PDF → เทียบกับ PDF ต้นฉบับ |
| สี/ผังใน Excel จริง | ExcelJS อ่านกลับได้ แต่ไม่ใช่การเรนเดอร์ | เปิดไฟล์ใน Excel ดูจริง |
| IndexedDB / persist / Safari gate | ต้องมี browser storage | ลองในเบราว์เซอร์ |

## วิธีเทียบ diff กับต้นฉบับ (ตอนแก้ผัง xlsx)

ไม่มี test ถาวรสำหรับเรื่องนี้ เพราะ "ถูกต้อง" ขึ้นกับว่ายึดหน่วยไหน
เวลาจะไล่ ให้เขียน test ชั่วคราวที่:

1. build workbook จาก fixtures
2. เปิดทั้งไฟล์เราและต้นฉบับด้วย ExcelJS
3. วนเทียบทีละเซลล์ — value, `numFmt`, `fill.fgColor.argb`, `alignment.horizontal`, `border`
4. เทียบ `worksheet.model.merges`, `getColumn(c).width`, `getRow(r).height`, `pageSetup`

จุดที่ต้องรู้เวลาอ่านผล:
- ต้นฉบับใช้ **shared formula** ExcelJS คืนเป็น object ไม่ใช่ `{formula}` → ดูเหมือน diff ทั้งที่เหมือนกัน
- เซลล์ merge จะคืนค่าเดียวกันทุกช่องในช่วง
- rich text คืน `[object Object]`

ลบ test ชั่วคราวทิ้งเมื่อไล่เสร็จ อย่า commit
