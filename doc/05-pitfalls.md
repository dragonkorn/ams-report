# กับดัก — อ่านก่อนแก้โค้ด

[← กลับสารบัญ](MOC.md)

ทุกข้อในนี้เคยเกิดจริงในโปรเจคนี้ ไม่ใช่ทฤษฎี

## 1. บันทึกรอบเดียวกันซ้ำคนละวันที่ → กริดย้ายช่อง เงียบสนิท

**อาการ:** ช่องเดือน ก.ค. ว่าง ตัวเลขไปโผล่ที่ ส.ค. · `5/12` กลายเป็น `6/12` · **ตัวตรวจ invariant ยังขึ้นเขียว**

**สาเหตุ:** สูตรย้อนกลับอาศัยจุดอ้างอิง `ytd − mtd` จากแต่ละ snapshot
ถ้ามี 2 snapshot ถือตัวเลขชุดเดียวกันคนละเดือน จุดอ้างอิงขัดกันเอง อันหลังทับอันแรก

```
30 ก.ค. บอก  ยอดถึงสิ้น มิ.ย. = 56    ยอดถึงสิ้น ก.ค. = 66
 9 ส.ค. บอก  ยอดถึงสิ้น ก.ค. = 56 ←ทับ  ยอดถึงสิ้น ส.ค. = 66

ก.ค. = 56 − 56 = 0   ว่าง
ส.ค. = 66 − 56 = 10  ย้ายไปเดือนถัดไป
```

**ทำไม invariant จับไม่ได้:** ผลรวมยัง 66 เท่าเดิม การตรวจดูแค่ผลรวม จับ "ตัวเลขย้ายช่อง" ไม่ได้

**ที่แก้ไว้แล้ว:**
- เทียบ `fingerprintOf(snapshot)` ก่อนบันทึก ถ้าตัวเลขชุดนี้เคยบันทึกไว้คนละวันที่ → เตือน + ปุ่มกระโดดไปวันที่เดิม
- แถบซ้ายโชว์รายการรอบที่เก็บไว้ พร้อมปุ่มลบทีละรอบ

**ถ้าเจออีก:** ลบรอบที่ผิดทิ้ง ไม่ใช่ไปแก้สูตร

## 2. ช่องวันที่ default เป็นวันนี้ → ทางที่ผิดคือทางที่ง่ายที่สุด

CSV ไม่มีวันที่อยู่ข้างใน ระบบเดาไม่ได้ ช่องจึง default เป็นวันนี้ (แก้ได้)
ตอนไล่ทดสอบด้วยไฟล์ย้อนหลังจาก zip จะผิดทุกครั้งถ้าลืมแก้ แล้วไปเจอกับดักข้อ 1

xlsx ที่นำเข้ามี `B4` เป็นวันที่ของตัวเอง — ใช้เช็คได้ แต่**อย่าผูกสองอย่างเข้าหากัน** ไฟล์เก่ากับรอบใหม่เป็นคนละวันโดยชอบธรรม

## 3. `db.units.update()` เงียบเมื่อยังไม่มี record

Dexie `update()` บน key ที่ไม่มีอยู่ **ไม่ทำอะไรและไม่ error**
เคยทำให้ import xlsx สำเร็จ ได้ตัวแทน 21 คน แต่ไม่มีหน่วย ไม่มี snapshot → แถบซ้ายว่าง ขั้น 3/4 ล็อก ผู้ใช้ตัน

**ใช้ `put()` แบบ merge แทนเสมอ** ถ้าไม่แน่ใจว่า record มีอยู่

## 4. ช่องว่างในกริดจาก xlsx = 0 ไม่ใช่ "ไม่รู้"

เดิม `seeded?.[m] ?? null` ทำให้ช่องว่างกลายเป็น null
ผลคือ `months.every(m => m != null)` เป็น false → **ข้ามการตรวจ invariant ไปเลย** ผิดแล้วยังขึ้นเขียว

xlsx ที่นำเข้าครอบคลุมทั้ง 12 เดือน ช่องว่างจึงหมายถึง 0
`seeded ? (seeded[m] ?? 0) : null` — มี seed = รู้ทั้งปี, ไม่มี seed = ไม่รู้

## 5. เซลล์ที่ข้ามไม่เขียน = ไม่มีเส้นขอบ

ตอน export xlsx เคย `return` ข้ามช่องเดือนที่ไม่มีค่า ผลคือช่องนั้นไม่มีทั้งสีและ**เส้นขอบ**
เปิดใน Excel เห็นเป็นแถบเทาทะลุ เพราะ Excel โชว์ gridline ตัวเองแทนเส้นตาราง

**ตีเส้นทุกช่องเสมอ ลงสีเฉพาะช่องที่มีค่า**

## 6. รหัสใหม่จาก CSV ถูกตั้งเป็น "ตัดสัญญา" เงียบ ๆ

ตอนบันทึก CSV รหัสที่ไม่เคยเห็นถูกสร้างเป็น `status: 'ended'` เพื่อไม่ให้โผล่บน report เอง
ได้ผลถูกโดยบังเอิญกับ 4 คนที่ตัดสัญญาไปแล้ว **แต่ตัวแทนใหม่ที่เข้าหน่วยจริงก็จะถูกซ่อนเหมือนกัน**

ตอนนี้ยังไม่มีอะไรแยก "ตัดสัญญาจริง" ออกจาก "ยังไม่ได้ตั้งค่า" — หน้าตัวแทนเตือนแค่เรื่อง MOC
ต้องเพิ่ม field (เช่น `statusConfirmed`) ถึงจะแยกได้ → [07-open-questions.md](07-open-questions.md)

## 7. ทศนิยมในคอลัมน์เงิน

ต้นฉบับใช้ `#,##0` ทุกช่องเงิน **ไม่มีทศนิยม** เก็บ `12345.4` แต่แสดง `12,345`
เคยแสดง `12,345.40` ทั้งใน HTML และ xlsx — ผิดทั้งคู่

Growth% ใช้ `General` → `1.7` ไม่ใช่ `1.70`
มีแค่ Limra % ที่เป็น `#,##0.00`

## 8. ชื่อไฟล์ CSV เชื่อไม่ได้

`AMSDailyKRAFyp.csv` เป็น Agency ใน VP7 แต่เป็น **Agent** ใน VP27
อ่านชนิดจากบรรทัด 1 และระดับจากบรรทัด 2 เท่านั้น

## 9. `?` ในชื่อไทยไม่ใช่ปัญหา encoding

`นา???สาว` · `ก???ีพร` — raw byte เป็น `0x3F` จริง ระบบต้นทางทำเสียเอง
อย่าไปไล่แก้ decoder ให้เสียเวลา ทางแก้คือช่องแก้ชื่อด้วยมือ

## 10. roster ไม่เท่ากันระหว่าง feed

VP82 รหัส `620992` มีเฉพาะไฟล์ FYC All → ต้อง outer join เติม 0
ใช้ inner join จะตกคนนั้นไป ซึ่งไม่ตรงกับ report ต้นฉบับ

## 11. Dexie compound key ลบด้วย `.delete([a,b])` ไม่ได้

ต้องใช้ `.where('[unitId+asOfDate]').equals([unitId, asOfDate]).delete()`
`Table.delete()` รับ key เดี่ยวเท่านั้น typecheck จับให้ แต่รู้ไว้ก่อนจะเร็วกว่า

## 12. อย่า replica ข้อผิดพลาดของต้นฉบับ

ไฟล์ต้นฉบับทำมือ มีพิมพ์ผิดจริง: `วันทิ่` แทน `วันที่` · `0` แทนช่องว่างใน x/12 · `1/12.` เกินจุด
ระบบทำให้ถูก ไม่ตามข้อผิดพลาด — แต่ต้องรู้ว่ามันมีอยู่ เวลาเทียบ diff จะได้ไม่หลง

**ช่องหมายเหตุสัญญาก็เป็นแบบนี้** ต้นฉบับสะกด `เกษีณอายุ` (ตก ย) และ `ต้องแก้Qนี้` (ไม่เว้นวรรค)
ปนกับที่สะกดถูก ซึ่งเสียหาย 2 ทาง: พิมพ์ผิดบน report **และ** แถวไม่ถูกทำเครื่องหมายแดง
เพราะโค้ดเทียบตรงกับ `NOTE_FIX_THIS_QUARTER`

`normalizeNote()` ใน [compute.ts](../app/src/lib/compute.ts) จับทุกสะกดให้เป็นรูปเดียว เรียกทั้งตอน
import จาก xlsx และตอน `buildReport` — ที่ต้องเรียกตอน build ด้วยเพราะข้อมูลที่ import ไปแล้ว
ยังเก็บสะกดเดิมอยู่ใน IndexedDB ช่องแก้มือในหน้า "ตัวแทน" ยังโชว์ข้อความดิบตามที่เก็บไว้

## 13. แต่ละหน่วยสไตล์ไม่ตรงกัน

สีหัว ความกว้างคอลัมน์ คำในหัวตาราง ต่างกันระหว่าง VP7 กับ VP82
**ไม่มี "ถูกต้อง" อันเดียว** — ตัวส่งออกยึด VP7 เป็นหลัก ถ้าจะให้ตรงทุกหน่วยต้องทำเป็นค่าตั้งต่อหน่วย

## 14. เปิดรอบเก่าแล้วส่ง `history` ทั้งก้อน → กริดโชว์อนาคต

`activeGrid` เดินทุก snapshot ที่รับมา ไม่สนใจว่ารอบที่แสดงคือรอบไหน
เลือกรอบ พ.ค. แต่ส่ง snapshots ครบทั้งปี → กริดเติมช่อง มิ.ย.–ส.ค. ที่ตอนนั้นยังไม่มีข้อมูล
report ที่ได้จึงไม่ใช่ฉบับที่เคยส่งจริง และ "ผลรวมกริด = งานอนุมัติสะสมปี" ก็เพี้ยนตาม

กติกา: กรอง `asOfDate <= current.asOfDate` **ก่อน** ส่งเข้า `buildReport` เสมอ ([App.tsx](../app/src/App.tsx))
