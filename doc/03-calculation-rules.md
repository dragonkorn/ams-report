## ขั้นบันได FYC

ใช้ **FYC All Product ช่อง YTD Current Year**

```
FYC < 120,000            →  ต้องมี 120,000   ยังขาด = 120,000 − FYC
120,000 ≤ FYC < 240,000  →  ต้องมี 240,000   ยังขาด = 240,000 − FYC
FYC ≥ 240,000            →  "ครบแล้ว"
```

ช่อง "ต้องมี FYC" ในไฟล์จริงมีแค่ 2 ค่านี้ ไม่มีค่าอื่นเลย
ถ้าใช้ FYC Life แทน All Product **จะไม่ตรงสักแถว**

## กริด Active 12 เดือน

ช่องในกริด = **จำนวนรายอนุมัติของเดือนนั้น** (Case ช่อง Current Year ไม่ใช่ Sub)

### สร้างย้อนหลังจาก snapshot

snapshot 1 อันให้ข้อเท็จจริง 2 อย่าง:

```
ytd − mtd  = ยอดสะสมถึงสิ้นเดือนก่อนหน้า   ← เดือนจบแล้ว แม่นเสมอ
ytd        = ยอดสะสมถึงสิ้นเดือนของตัวเอง  ← ยังไม่นิ่งถ้า snapshot กลางเดือน
```

เก็บเป็นชุดยอดสะสม แล้วลบกันทีละคู่ ได้ยอดรายเดือนกลับมา
`cumulative[0] = 0` (ก่อนมกราคมไม่มีอะไร)

```
เดือน m = cumulative[m+1] − cumulative[m]
```

เดือนที่คำนวณไม่ได้ ตกไปใช้ค่าจาก `seededGrids` (นำเข้าจาก xlsx เดิม)

### ยืนยันแล้ว

- **ช่องเดือนปัจจุบัน = Case `MTD Current Year` เป๊ะทุกแถวทั้ง 5 หน่วย**
- **ผลรวมกริด 12 เดือน = Case สะสมปี ตรง 50/50 แถว รายคน ไม่ใช่แค่แถวรวม**

ใช้เป็น invariant ตรวจก่อน export ถ้าไม่ตรง = snapshot ขาดเดือน
**แต่จับ "ตัวเลขย้ายช่อง" ไม่ได้** เพราะผลรวมไม่เปลี่ยน → [05-pitfalls.md](05-pitfalls.md)

### x/12

นับเดือนที่มีค่ามากกว่า 0 · **ถ้าเป็น 0 เว้นว่าง ไม่พิมพ์ `0/12`**
ช่องกริดค่า 0 ก็เว้นว่างเช่นกัน

ในต้นฉบับมีพิมพ์ผิดมือ 2 จุด (VP27 พิมพ์ `0` · VP90 พิมพ์ `1/12.`) — ระบบทำให้ถูก ไม่ replica ตามข้อผิดพลาด

## แถบสี Limra

ไฟล์ต้นฉบับ **ไม่มี conditional formatting เลย ระบายมือทั้งหมด**
เส้นแบ่งด้านล่าง reverse จากค่าจริงราว 100 ช่อง:

```
≥ 100         เขียว  #CCFFCC
90 – 99.99    เหลือง #FFFF00
80 – 89.99    ส้ม    #FFC000
< 80          แดง    #FF0000
```

ค่าคงที่ `LIMRA_ORANGE_FLOOR = 80` — เจ้าของงานยืนยัน ตรงกับ `ขั้นต่ำ 80%` บนแถบ CAREER

ไฟล์ 30 ก.ค. ระบายมือ เส้นจริงในไฟล์ตกอยู่ที่ 84 (84.03 แดง · 84.04 ส้ม) และมี 77.29 ทาพีช
**ถือว่าทาพลาด ไม่ใช่กฎ** — เกณฑ์คือ 80

**เบี้ยหายไปเป็น 2 ค่าอิสระ ไม่ใช่ค่าเดียวแสดง 2 ที่** ต่างกัน 18 จาก 50 แถว
เช่น VP7 อารีย์ `98,400` vs `90,200` · ระดับหน่วย VP7 `512,300` vs `340,100`

Limra ไม่มีไฟล์ต้นทาง พิมพ์มือล้วน 4 ค่าต่อคน + 4 ค่าระดับหน่วย
ระบบหยิบ **ค่าล่าสุดที่มี ณ วันของรอบ** ไม่ต้องตรงวันเป๊ะ — xlsx เดือนก่อนก็ใช้ได้

## เงื่อนไข MOC — เดาจากปีไม่ได้

ใช้เป็น *ค่าแนะนำ* เท่านั้น:

```
ออกรหัส ≤ 2556  →  "Q ละ 1 ราย"
ออกรหัส ≥ 2561  →  "Q ละ 3 รายหรือเบี้ย25,000"
```

ข้อมูลจริงหักล้าง:

| รหัส | วันออกรหัส | MOC จริง |
|---|---|---|
| 450558 (VP27) | 15/09/2558 | Q ละ 1 ราย |
| 450178 (VP87) | 25/09/2558 | Q ละ 3 รายหรือเบี้ย25,000 |
| 470769 (VP27) | 18/10/2016 (ค.ศ.) | Q ละ 1 ราย |
| — (VP82) | ปี 2525 | Q ละ 3 รายหรือเบี้ย25,000 |

**ห่างกัน 10 วันได้คนละเกณฑ์** → เป็นช่องเก็บถาวรรายคน ระบบเสนอค่า คนยืนยันครั้งเดียว
ข้อความมี 2 สะกด (`เบี้ย25,000` / `เบี้ย 25,000`) normalize ตอนนำเข้า

## วันที่ออกรหัส — free text

เจอจริง: `21/32551` · `26/122544` (ขาด `/`) · `18/10/2016` (ค.ศ.) · zero-pad ไม่คงที่
เก็บเป็น string ตามที่พิมพ์ · parse แบบ best-effort เพื่อแนะนำ MOC เท่านั้น · **ห้าม validate แข็ง**

## ชื่อย่อ

```
0000100017 : นาย สมชาย ใจดี   →  100017 : สมชาย ใ.
```

ตัดศูนย์นำหน้า → ตัดคำนำหน้า → ชื่อจริง + อักษรแรกนามสกุล + จุด

คำนำหน้าตัดแบบ prefix ไม่ใช่แยกด้วยช่องว่าง เพราะบางแถวไม่มีเว้นวรรค:
`นางสาวชูใจ รุ่งเรืองทรัพย์` → `130388 : ชูใจ ร.`
ลำดับสำคัญ — ต้องเช็ค `นางสาว` ก่อน `นาง`

## ปีในหัวตาราง

```
ปีข้อมูล   = ปี พ.ศ. ของ asOfDate    (ก.ค.2026 → 2569)
ปี CAREER  = ปีข้อมูล + 1            (→ 2570)
```

## สถานะสัญญา — 3 ระดับ ไม่ใช่ 2

```
มีผลบังคับ     → ขึ้น report
พักสัญญา       → ขึ้น report + ไฮไลต์เหลือง + หมายเหตุ "ต้องแก้ Q นี้"
ตัดสัญญา       → ไม่ขึ้น report แต่เก็บไว้ใน DB ไม่ลบ
```

ยืนยันจากไฟล์: คนพักสัญญาอยู่ใน report ทั้ง 3 คน (VP7 130883 · VP27 570939 · VP82 600670)
สอดคล้องกับคำเตือนท้าย report ว่าพัก 2 ครั้งใน 1 ปีจะถูกตัดสัญญา — พักคือยังกู้ได้ ต้องเห็นเพื่อไปตาม

**คนตัดสัญญาห้ามลบทิ้ง** CSV ส่งชื่อมาทุกเดือนตลอดไป ถ้าไม่จำสถานะจะถามซ้ำทุกรอบ
